# ngui-efficacy

_No findings._

## Reasoning

Audited all 10 active, non-waived NGUI requirements against 19 test methods across 4 test files. Checked the resolved-findings ledger (NGUI-AQ-1 and WAIVE-1 are the relevant prior rulings) and all 12 audit conduct articles before finalizing.

BEHAVIORAL COVERAGE: All 10 tested REQs have citing tests that exercise the described behavior. REQ-NGUI-1.3 and 1.3.1 are tested for both CLIs (exit codes and stderr content). REQ-NGUI-1.5 is tested across 5 distinct account operations (Create, FetchByParentCode, Deactivate, UpdateName, UpdateExternalReference), each with typed error matching via isCorrectError. REQ-NGUI-3.6/3.7/3.8/3.9 cover the main CLI's stdout, stderr, case sensitivity, and unknown-command behaviors. REQ-NGUI-4.2/4.4/4.5 cover the Reports CLI's case sensitivity, success/failure paths, and unknown-report-name behavior. I verified each test body against the REQ text to confirm the right property is being checked.

ASSERTION QUALITY: Applied the smell test and all 10 specimen patterns. Process-level tests (SonOfLeoCli/Program.fs, Reports/Program.fs) use exit-code assertions, which is correct per the test doctrine and Specimen 5 guidance -- these ARE ProgramTests checking the process boundary. Route-level tests (ReportRoutes.fs, AccountRoutes.fs) use typed error matching via isCorrectError/isCorrectErrorString, which satisfies Specimen 4's after-pattern (DU case name matching with both escape arms). The REQ-NGUI-3.6 stdout test deserializes the CLI output and asserts a value, proving the payload is real data. The REQ-NGUI-4.4 stdout test deserializes to TrialBalanceReturn and checks the DU variant; content verification is at the route level (REQ-RPT-2.2). Considered whether the Reports stderr test (line 45) is Specimen 6 because it derives the expected error from FileIO.writeTextFile which is also in the CLI's call chain -- concluded it is not, because the test is verifying error transport (does the error reach stderr?), not error computation, and the two sides CAN diverge (if the CLI reformats or drops the error). Considered whether SonOfLeoCli's hard-coded "Money Market" (line 55) is Specimen 1 -- the fixture is available but unused. However, this is a process-level plumbing test where the value assertion is supplementary evidence that stdout carries real data, not a business-logic assertion. The SonOfLeoCli Assert.Contains on stderr is covered by NGUI-AQ-1 (overruled).

NEGATIVE COVERAGE: All REQs with explicit rejection behaviors have negative tests. REQ-NGUI-1.5 has 5 dedicated failure tests. REQ-NGUI-3.8 has 2 case-sensitivity failure tests (domain and verb). REQ-NGUI-3.9 has unknown-command error tested with typed error in stderr. REQ-NGUI-4.2 has case-sensitivity failure test. REQ-NGUI-4.5 has tests at both route level (typed error match) and process level (stderr content + exit code).

UNCITED BEHAVIOR: No NGUI-specific tests exercise uncited logic. Other route files (JournalEntryRoutes, IngestionRoutes) test AccountCodeDoesntMatchAccountId but cite their own domain REQs (JE-3.9, etc.), which is appropriate. The CLI source code's --file flag handling is covered by REQ-NGUI-3.10 (waived). The no-argument usage-message edge case in both CLI sources is implicitly covered by the broad waivers on REQ-NGUI-3.1-3.5. No code paths in SonOfLeoCli/Program.fs or Reports/Program.fs lack REQ coverage.

The 17 waived requirements were reviewed for soundness against the WAIVE-1 precedent (overruled; "too broadly scoped" is an accepted waiver reason). No waiver reasons appeared unsound.
