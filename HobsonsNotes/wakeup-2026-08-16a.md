## Where we are

Branch `data-ingestion`. The entire ingestion pipeline is code-complete:
ingest → dedup → classify → manual review → shadow post → batch post.
All wired end-to-end through CLI routes. Zero test coverage — BD is
writing tests now.

**What exists:**

- **Ingestion:** `IngestRawFileToStage` route. Reads JSONL, validates,
  persists, deduplicates, classifies, moves file to processed dir.
  Returns `IngestionFullResult` (staged entries + duplicates +
  classification results).

- **Deduplication:** `StageEntryHeader.fetchDuplicates` — CTE-based SQL
  query joining `ingestion.staged_entry` against both
  `ledger.journal_entry_ext_reference` (stage-vs-ledger) and itself
  (stage-vs-stage, using first audit timestamp for precedence). Dedup
  key: `source_id + fi_reference`. Nothing else participates.

- **Classification:** Pure classifier in `Classifier.fs` (rules engine),
  orchestration in `StageEntryOrchestration.classifyStagedEntries`.
  Authority hierarchy: parser > classifier > operator. Fully
  parser-assigned entries skip classification and auto-transition to
  `Classified`. Entry-level status derived from worst line outcome:
  any `ManyMatchesTied` → `Conflict`, any `NoMatch` → `NoMatch`,
  all matched → `Classified`.

- **Manual review:** `UpdateStageEntry` route. Full operator control over
  all fields. Status is caller-set, not auto-inferred. System validates
  composite after update (balanced entry, valid codes, legal transition).

- **Shadow post:** Same code path as batch post, different transaction
  disposition. `PostStageEntries` route with `isShadow` flag. Returns
  before and after trial balance. Shadow always rolls back.

- **Batch post:** One JE per staged entry through the existing domain
  model. External reference from source name + fi_reference. All-or-
  nothing transaction. Status → `Posted` with `LedgerPoster` mechanism.

- **Classification rules CRUD:** Create, fetch (by ID/name/filtered),
  activate/deactivate. JSONB persistence for rule groups. Domain model:
  `FieldMatch` → `FieldMatchChain` → `ClassificationRuleGroup` →
  `ClassificationRule`. Priority: lower int wins.
