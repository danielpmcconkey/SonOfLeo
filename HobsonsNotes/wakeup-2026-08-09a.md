## What happened this session (2026-08-08 through 2026-08-09)

### Design session (2026-08-08)

Long design conversation starting from a GAAP question about whether JE
posting should validate offset between normal balance types. Conclusion:
that check is algebraically equivalent to debits=credits, which SonOfLeo
already enforces. Dan ran queries against leobloom_prod to confirm — zero
imbalanced JEs across the entire history.

This pivoted into staging domain design:
- **Flat vs nested staging:** Started flat (one row per FI transaction),
  but Dan's multi-line JE data (payroll 11 legs, tenant rent splits 3 legs,
  mortgage P&I 3 legs) proved flat insufficient. Moved to two-table
  normalized: staged_entry (header) + staged_entry_line.
- **Parser latitude:** Parsers own decomposition. A payroll parser produces
  10 fully-assigned legs. A simple bank CSV parser produces 2 legs (cash
  known, expense unknown). Classification handles only the unknown accounts.
- **Shadow post = real post in rolled-back transaction.** Dan's requirement
  — shadow post must go through the full domain model validation.
- **Account codes, not IDs.** Dan corrected my initial spec — the review
  surface and classification rules speak codes. IDs are resolved at post time.
- **fi_reference required.** Dan's call — every parser must produce a dedup
  key. No class of transaction is invisible to dedup.
- **No back-trace.** No journal_entry_id on staged_entry, no
  journal_entry_line_id on staged_line. External references provide
  provenance.
- **Schema name `ingestion`**, not `stage`. Staging is a piece of the
  domain, not the domain.

### Dan's implementation (2026-08-09)

Dan built the full foundation layer while I wasn't looking, then asked me
to review. Key decisions Dan made during implementation:

- **`Read` status removed.** Initially added as "parsed but not persisted"
  — Dan realized it would be immediately overwritten before ever being
  persisted. Entries go straight to `Ingested`.
- **`Ignored` status added.** For entries with source data problems that
  shouldn't be posted but must block re-import. Dedup treats Ignored as a
  match (REQ-STG-4.5). Any non-terminal status can transition to Ignored.
- **`NoMatch` over `unclassified`.** More precise — means the classifier
  ran and found nothing, not "hasn't been classified yet."
- **`ingestion.source` entity.** Normalized FI source into its own table
  with CRUD. Replaces a varchar fi_source with a proper FK.
