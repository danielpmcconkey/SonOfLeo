## What happened since wakeup-2026-08-16a

### Bug fixes

- **`classifyMatchCandidatesAndUpdateLines` wasn't updating lines.**
  BD caught it — the function ran the classifier but never called
  `updateDbLinesFromResultsList`. One-line fix (`893878a`).

- **Timestamp collision in audit records.** `ingestRawToStageThenDeduplicateAndClassify`
  used one context for all three operations, so all audit records shared
  the same instant. Made `List.sortByDescending instant` unpredictable.
  Fix: `Context.updateInitiationInstant` bumps the timestamp between
  ingestion, dedup, and classification phases (`e068379`).

- **Same-file duplicate detection.** BD found that two entries in the
  same file with the same `source + fi_reference` slipped through dedup
  because the `<` timestamp comparison can't distinguish entries ingested
  in the same batch. Dan's decision: **this is a parser defect, not a
  dedup concern.** Same-file duplicate `fi_reference` should be caught at
  ingestion validation in `constructSetFromRaw`, not by the dedup query.
  BD reworked the query to detect this case (`1f62de8`).

- **`Utilities.fsproj` HintPath fix** (`e0d905d`) — had `<Reference>`
  with `<HintPath>` pointing at Dan's NuGet cache instead of
  `<PackageReference>`. BD was blocked on build.
