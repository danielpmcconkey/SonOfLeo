## What happened since the last wakeup (2026-09-06a)

30+ commits across five days. The highlights, grouped by theme:

### Flow revised (2026-09-07)

Dan broke the state machine into three clear boundaries: raw ingestion,
account matching, and cash flow. The state machine dies after producing
a final report. Hobson drives the posting boundary manually. This
supersedes the old draft's Phases 4-9 for ordering and step ownership.

Key changes from the 09-06 design:
- **One classification step per claimant kind**, not one step with two
  internal passes. Account classification is `StageEntryOrchestration`,
  PA classification is `CashFlowOps`. Each mints its own run ID.
- **ProcessObligations folded into Task 8** — invoice matching and
  payment creation happen inside `classifyPaymentAgreements`, not as a
  separate CLI step.
- **Scaffolding-first build approach** — all return types, stubs, and
  routes land before implementation. Dan: "these workflow problems don't
  show up until I see how you're connecting the dots."

### Architecture decisions settled

- **Decision 15:** TransactionPointer moved to line level on both sides
  (`Posted of JournalEntryLineId | Staged of StageEntryLineId`). Deletes
  the "one line per leg per entry" assumption.
- **Decision 16:** Diagnostic table records matches only, not analysis.
  One row per matched rule, not per candidate.
- **Decision 17:** No priority column on the diagnostic row, no update
  function. Rows are immutable.
- **Authority hierarchy formalized:** Dan > Hobson > import script >
  classifier. A value written by a higher authority is never a candidate
  for a lower one.
- **Back-linkage from stage to ledger** (`de394fa4`) — reverses a prior
  spec decision (REQ-STG-2.8 withdrawn 2026-08-08). Stage entries now
  carry `journalEntryHeaderId` and `journalEntryLineId`, written at
  posting time. This is what makes `TransitionPaymentsToPosted` a lookup
  instead of a derivation.
