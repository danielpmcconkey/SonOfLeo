## What happened this session (2026-08-10 through 2026-08-14)

### Classification engine design (2026-08-10)

Long design conversation. Researched Plaid, Firefly III, Actual Budget,
beancount/hledger classification approaches. Analyzed all 2,218 existing
LeoBloom merchant rules from `stage.merchant_rules`. Key decisions:

- **Structured domain model, not raw SQL.** Started with a compiled-SQL
  CASE statement approach, pivoted away due to SQL injection surface.
  Landed on: `FieldMatch` DU evaluated in F# via .NET regex. No SQL
  interpolation.
- **Priority: lower int wins.** Dan's call.
- **JSONB for rule body, relational columns for metadata.** Rule groups
  stored as JSONB in a single column; priority, account_code, name,
  is_active as proper columns.
- **Conflict detection is a rule-creation concern, not classification-time.**
  The classifier returns `OneMatch` or `ManyMatches` — the orchestrator
  decides what to do. `Conflict` as a staged entry status may be dropped
  from the spec.
- **`ingestion.source` is a static lookup.** Create route only, no
  edit/delete routes. Direct DB correction for the rare fix, same
  philosophy as COA renames.
