## What happened since wakeup-2026-08-22a

### Code-to-ID migration (Dan)

Dan pivoted staged lines and classification rules from storing account
codes (strings) to account IDs (UUIDs with FK to `ledger.account`). This
was action item 27a but snowballed into a design-level change:

- `StageEntryLine.accountCode` → `.accountId` (AccountId option)
- `StageEntryLineFieldUpdates.accountCodeUpdate` → `.accountIdUpdate`
- `ClassificationRule.codeAtMatch` → `.accountIdAtMatch`
- `PrioritizedMatch.code` → `.accountId`
- `BaseStageRawRow.accountCode` → `.accountId`
- Two new migrations: `202608220920-RebuildClassificationRule.sql` and
  `202608220946-RebuildStageEntryLine.sql`. Both tables now have real FKs
  to `ledger.account(unique_id)`.
- `makeRawRow` test helper now takes `context` as first argument (code-to-ID
  resolution at construction).
- New error case `AccountIdDoesntMatch` for model-level ID validation;
  `AccountCodeDoesntMatchAccountId` still fires at the boundary.
- `LookupCache` refactored (8418c8f): 5 copy-pasted caches → 2 builder
  functions + 5 one-liners. `accountIdToName` added for REQ-NGUI-1.6.

Account name added to all ingestion return types: `ClassificationRuleReturn`,
`PrioritizedMatchReturn`, `StageEntryLineReturn`. The original disposition
excluded StageEntryLineReturn (no FK); exclusion reversed now that the FK
exists.

Dan fixed a `desc` bug in `ClassificationOrchestration.fs` line 113 — the
sort clause for AccountCodeDesc was missing the `desc` keyword. BD's sort
test caught it.
