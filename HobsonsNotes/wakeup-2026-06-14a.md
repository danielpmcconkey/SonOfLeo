## What happened this session

### Environment isolation (Hobson + Dan, fully implemented)

Designed, FMEA'd (by BD), revised, and executed a full environment
isolation plan. The problem: Dan develops on the host (production
environment), and running anything from Rider hit the prod database.

**What we built:**
- Three postgres roles (`sonofleo_dev`, `sonofleo_test`, `sonofleo_prod`)
  each locked to their own database via `pg_hba.conf` reject rules.
- Connection strings stored as env vars (`SONOFLEO_DEV_CONNSTR`,
  `SONOFLEO_TEST_CONNSTR`, `SONOFLEO_PROD_CONNSTR`) in a single source
  file: `~/.config/environment.d/sonofleo.conf`, sourced by `.bashrc`.
- Appsettings files contain the **name** of an env var, not a connection
  string. `appsettings.Development.json` → `SONOFLEO_DEV_CONNSTR`,
  `appsettings.Production.json` → `SONOFLEO_PROD_CONNSTR`. Test project's
  `appsettings.Development.json` → `SONOFLEO_TEST_CONNSTR`.
- `.fsproj` build targets copy the right appsettings file to
  `appsettings.json` in the output: Debug → Development, Release →
  Production. No env var needed to select the environment.
- DAL.fs simplified: `getEnvironment`, `getTemplate`, `injectPassword`
  all deleted. Replaced with a single chain: load `appsettings.json` →
  read env var name → read connection string from env var.
- BD's container (`compose.yml`) updated with the dev and test connection
  strings (using `172.18.0.1` as host). No prod in the container.

**Key discovery:** Rider launched from a desktop shortcut (ELF binary)
doesn't inherit `.bashrc` env vars. Solution: Dan launches Rider from a
terminal (`rider` command, symlinked to `rider.sh`). The `environment.d`
/ D-Bus injection approaches both failed on Cinnamon.

  env vars. Desktop shortcut / file manager double-click won't work.
- **Passwords in env vars need single quotes** in `sonofleo.conf` because
  they contain shell metacharacters (`<`, `>`, `&`, `|`).
