# Wakeup — 2026-06-25a

## What happened this session

Continuation of the JournalEntry slice on `core-je-model`. Three major infrastructure changes plus substantial JE model work.

**Typed error DUs — killed:** Discussed at length, decided `Result<T, string>` is the right fit. This is an atomic-process app — errors are surfaced to the actor for retry, not programmatically branched on. Removed the Typed Errors section from Doctrines.md and fixed the stale `Result<T, TError>` reference in the Constructor Rule.

**DbTransaction support:** Added optional `DbTransaction` parameter threading through the entire stack. DAL gained `createDbTransaction`, `commitDbTransactionAndDisposeConnection`, `rollbackDbTransactionAndDisposeConnection`. All three DAL execute functions (`executeNonQuery`, `executeReaderQuery`, `executeScalar`) accept `DbTransaction option` — `None` preserves existing behavior, `Some` reuses an open connection+transaction. Threaded through every function in Account, FiscalPeriod, JournalEntryHeader, JournalEntryLine, JournalEntryComponent, all CLI routes, all tests, and all cleanup functions. The `DbTransaction` type is opaque outside the DAL (private record). Design: orchestrator creates the transaction, passes `(Some transaction)` down, commits or rolls back. Individual functions never inspect the option — only the DAL does.

**Test cleanup pattern:** Converted all Account and FiscalPeriod integrated tests from manual `idToCleanUp` / `cleanUpAccountId` pattern to transaction-rollback cleanup. Create transaction at top, pass `(Some transaction)` everywhere, rollback in `finally`. No mutable cleanup state, no orphaned rows. CLI route tests left on the old pattern (subprocess can't share a transaction).

**FiscalPeriod constructOmni restructured:** Now takes raw key string, validates it, and derives start/end dates internally. DB stores the dates as a query convenience (denormalization), but they are not a source of truth — constructOmni re-derives them on reconstitution.
