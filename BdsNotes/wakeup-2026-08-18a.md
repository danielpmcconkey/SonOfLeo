## What happened

Went in with 5 unexplained integrated failures and 13 route stubs. Came out with 0 real
failures and 5 stubs. The 5 failures were 3 bugs.

### The empty-list-as-error bug, twice

`fetchAllForPosting` and `fetchAllByFile` both call `fetchByHeaderIdList`, which returns
`Error IngestionStageHeaderIdListCannotBeEmpty` on an empty list. So neither could ever
return `Ok []`, and "nothing to post" / "nothing left after dedup" were unrepresentable.
Fixed in `27f12945` and `4f01d15e`, one guard line each.

**Why the prior session went in circles:** the error message named `post`, so the hunt went
into posting. But `post` had already succeeded — the error came from the *verification line
after it*, `fetchAllForPosting` returning nothing. Do not trust the function an error names.

### Stage-vs-stage dedup

The strict `<` on `earliest_status_time_stamp` was doing two jobs at once — exclude self,
and earlier-one-wins. Two entries inserted in the same batch share an instant, so it failed
in both directions and neither was flagged. Rewritten as a `row_number()` partitioned by
source + `fi_reference`, ordered by `modified_at nulls first, unique_id`; `ordinal > 1` is a
duplicate. `1f62de87`, cleanup in `7e6bb493`.

Hobson argued for rejecting the file at ingestion instead. Overruled — REQ-STG-7.2 says flag
as duplicate, and the fail-open direction is the dangerous one.

### The JSON boundary had never been validated

`ingestRawEntries` deserialized straight into the domain type `BaseStageRawRow`.
`JsonFSharpConverter` builds private types by reflection, so **7 of 8 field validations never
ran** — an over-max amount and a 1001-char description reached staging. The documented flat
file format also could not parse at all (`Money` wanted `{"amount":32.47}`, `entryType`
wanted `{"Case":"Debit"}`). Fixed with a `BaseStageRawRowInput` primitives contract plus a
boundary converter in `989013e4`. Orchestrator tests never caught it because
`StageTestData.makeRawRow` builds rows in F# and walks past the boundary entirely.

### Visibility cleanup

Nine orchestration `confirm` functions made private in `f753645`. Only 2 of 11 public ones
ever had a caller outside their own file. Six isolated tests were reaching past them;
reconceived in `45694e0` — the JournalEntryComment ones were pure duplicates of existing
integrated coverage and got deleted, REQ-JE-1.24 moved to `JournalEntryCreation.fs`.

### Doctrine recorded

`000028d` — **a failure vector is a failed user interaction, not a technical failure mode.**
Dan's framing. "Test each vector once at its lowest level" is correct; the trap is counting
vectors as failure modes, which makes route-level validation cases look redundant. They
aren't — "the constructor rejects a bad value" and "the caller gets back an error naming the
right field" are two vectors with two different actors. Article, `Tests/README.md`, and
TestWriter rule 4.
