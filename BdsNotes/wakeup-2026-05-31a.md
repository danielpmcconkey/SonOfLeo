## What happened this session

Pivoted from spec-vetting to standing up the real project structure. Key
decisions, all made deliberately with Dan driving:

- **Layering is horizontal, not vertical.** Confirmed by auditing elder's
  actual project graph (`/workspace/LeoBloom` `.fsproj` references):
  - `Model` = pure **types**, all contexts in one project, one file per
    context (`Ledger.fs`, later `Ops.fs`, `Portfolio.fs`). Mirrors elder's
    `LeoBloom.Domain`. Renamed from "Domain" because that name oversells a
    types layer (Dan's call, good one).
  - `Ledger` / `Ops` / `Portfolio` (+ elder also has `Reporting`) = **behavior**
    (services, repos). Each context appears **twice**: its types in
    `Model/<context>.fs`, its behavior in the `<context>` project.
- **Dependency DAG** (from elder's refs + DB FK verification):
  ```
  Model        -> nothing
  Ledger       -> Model
  Portfolio    -> Model            (independent of Ledger — verified)
  Ops          -> Model, Ledger    (NOT Portfolio — verified)
  SonOfLeoCli  -> everything
  ```
- **Corrected Dan's "ops FKs to both" hunch.** Checked elder's *code* (not just
  the dev DB, which diverges from prod): ops references ledger only, never
  portfolio. Portfolio is an island. (First I wrongly checked the dev DB, then
  the migrations — Dan had to redirect me twice to the actual `.fsproj`/domain
  code. The code is the schema-of-record.)
- **Naming locked:** bare lib names (`Model`, `Ledger`); `SonOfLeoCli` is the
  front-door executable (NOT `SonOfLeo.Cli` — a binary named `Cli` on PATH is
  useless, and it distinguishes from a future `SonOfLeoWeb`); tests mirror 1:1
  as `Tests.Model` / `Tests.Ledger`. All projects under `src/` and `tests/`.
- **dotnet/Rider accord reached** (Dan lives in Rider, rarely uses the CLI):
  Rider solution folders are *logical* and don't map to disk — that's why Rider
  created `Model` at repo root while showing it under `src/`. Accord: Dan owns
  project structure through Rider; BD verifies via `dotnet build` from the
  terminal; **BD does not edit `.slnx`/`.fsproj` while Rider has the solution
  open** (clobber risk).
- Dan did the housekeeping himself (moved Model under src, stood up Ledger,
  split the tests). BD's job was audit-only.
