## What happened

Entirely strategy and design. Started as a question about F# coverage tooling in Rider,
became the design of a ledger-hardening campaign.

**Coverage tooling, resolved.** dotCover is dotUltimate-only — not in the free
non-commercial Rider license, not in a Rider-only paid one. BD initially said otherwise
and was wrong. Code Vision does not do F#; Dan sees only the VCS blame line. Free path
is coverlet plus ReportGenerator, but it was deprioritized: the interesting gaps here
are not line coverage.

**Dan's four-phase campaign, recorded in `05-ledger-hardening-strategy.md`.** The ledger
is the keystone; it gets over-tested before anything is built on it. Phase 1 gives every
interface contract input a distinct error. Phase 2 tests every error code. Phase 3 gives
every observable behavior an REQ. Phase 4 tests or waives every REQ. Iterative, per use
case, across all current use cases. Scope is *proving what exists is bulletproof* — not
finding unimplemented rules. Those live in the audit backlog and Dan owns them.

**Phase 1A is done** — `06-phase-1a-granularity-gaps.md`. Three parallel agents traced
every input contract field to the `AppError` cases it can reach. Five accidental field
collisions, seven relational ones, four operation-attribution gaps in the multi-purpose
`FiscalPeriodInput`, and eleven fields that lose list position.

**Case-vs-payload is settled: case-per-field.** BD argued twice for payload and lost
both times. Position does not need carrying — the payloads already hold the offending
value, and the consumer is Hobson, an agent holding the request it just sent, which
self-locates. Structural field binding is not needed for the same reason. What decided
it: if an LLM is reading `toMessage` prose, that sentence is the API, and a distinct
case earns a hand-written message where a payload gets a template.
