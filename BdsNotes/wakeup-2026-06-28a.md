# Wakeup — 2026-06-28a

## What happened this session

Massive two-day session (06-27 and 06-28) covering architecture, CLI wiring, and a UUID-purity push across the entire codebase. Eight commits on `core-je-model`.

**ModelOrchestrator introduced:** New project layer between Model and CLI. JournalEntry aggregate (type, creation, fetching, voiding) and Account deactivation (with new zero-balance and post-date JE validations) moved here. Split into three files: JournalEntryCreation.fs, JournalEntryFetching.fs, JournalEntryVoiding.fs.

**buildReadQuery centralized in DAL:** Replaced copy-pasted query assembly across all readRowsFromDb functions. Supports table aliases, joins, groupBy, orderBy. All model read functions converted.

**UUID-purity push:** All Model and Orchestrator functions now operate on UUIDs, never on codes or keys. Removed all `ByCode`/`ByKey` wrapper functions from Account and FiscalPeriod. String-to-UUID resolution happens at the CLI boundary.

**LookupCache:** Generic memoized lookup class (`Cache<'K,'V>`) in Model/LookupCache.fs. Pre-loads all rows at first access, falls back to single-row DB query on cache miss. Instances: `accountCodeToId`, `accountIdToCode`, `fiscalPeriodKeyToId`. Used by CLI routes for boundary resolution. One usage in Model layer: `EntryDate.create` uses a transaction-aware `FiscalPeriod.fetchIdByKey` instead of the cache (so tests can see uncommitted data).

**JournalEntry CLI fully wired:** All 9 routes implemented — PostNew, FetchById, FetchByPeriod, FetchLinesByAccount, FetchByExternalReference, Void, UpdateExternalReference, AddExternalReference, AddComment, UpdateComment. Full conversion functions for input→primitives and model→return types. Result railway throughout (no failwith on user input paths).

**Money renamed:** `Money` → `MoneyRecord`, `MoneyFunctions` → `MoneyModule`. Propagated everywhere.

**Void orchestration (REQ-JE-4.4):** `voidJournalEntryOrchestration` atomically voids the header and attaches a mandatory reason comment. Returns full JournalEntry aggregate. Old `voidById` removed from JournalEntryHeader module.

**REQ-JE-5.4 overruled:** `updateComment` now allows updating the secondary journal entry link. Spec updated.

**REQ-JE-4.10 added:** New requirement for appending external references to existing entries.

**Validation Location Doctrine added (Doctrine 3):** Default: validate in F#. Exception: pure data questions with no domain types load-bearing AND (exceptional complexity OR significant performance cost).

**REQ traceability audit:** Full pass through JournalEntryCrud.md. Fixed mis-tagged annotations (1.44/1.45, 2.9, 4.9). Added missing annotations across all sections.

**fetchByPeriodKey rewritten:** JournalEntryHeader.fetchByPeriod now filters on `je.fiscal_period_id` directly instead of joining to fiscal_period and filtering by key. Comment added explaining why `fiscal_period_id` isn't in the select columns (it's embedded in EntryDate, re-derived on reconstitution).

**Error messaging improved:** All CLI routes use `Result.mapError` with descriptive messages for cache lookup failures. Account return conversion returns Result instead of using failwith.

**Ledger project deleted.** Empty scaffold removed.
