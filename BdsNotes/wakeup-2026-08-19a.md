### Tests fixed

- **9.3 / 9.4 / 9.5** had no assertions at all — three tests whose bodies were `do! postStageEntry`
  and nothing else. Now post, refetch, and assert values. Each locates its entry by a field it
  does not itself assert on, because searching by a value and then asserting that value proves
  only that the filter works.
- **9.8** moved from the orchestrator to the route. Atomicity is a property of the transaction
  and every orchestrator test runs inside one that rolls back regardless, so a partial batch and
  a full rollback were indistinguishable from in there.
- **8.4** lost its orchestrator test, which was a copy of the 9.1/9.2 test and asserted the
  opposite of the requirement, passing only because it read its own uncommitted writes. The
  route-level shadow test carries the tag now.
- **8.3** asserted two trial balances were non-empty. Now derives which entries will post, sums
  their debits and credits per leaf account, and asserts the balance moved by exactly that.
- **4.4** asserted the account_code clause Dan removed from the spec, and could not see an
  under-return at all — it iterated whatever came back. Now set equality against a
  status-derived expectation, plus a stripped-code entry proving the filter does not exclude it.
- **9.1** renamed to `batch post happy path` and left deliberately toothless; **9.2** moved to
  the two tests that witness its clauses.
- **9.7** was `List.head` on a requirement about *each* staged entry. Now checks every entry.
  Found by the new grader agent, not by me — I had read that test twice this session.
- **Six untyped `| Error _ -> Ok ()` arms** typed properly. Converting them to *report* what they
  had caught revealed four were passing on a raw DAL error leaking to the caller. Dan fixed the
  lookups; the tests now assert `IngestionSourceNameNotFound` and `AccountCodeDoesntMatchAccountId`.
