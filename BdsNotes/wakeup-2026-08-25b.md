## Known-weak — do not trust these

**The REQ-STG-7.2 partial-key test and the REQ-STG-7.3 test both assert `0`.** A count of
zero is what an entry looks like when the pass never ran. Both carry a positive control in
the same batch for that reason — the pair sharing both keys, and the entry matching both
ledger fields. If you ever restructure either test, the control is not decoration; removing
it makes the remaining assertions unfalsifiable.

**`REQ-AC-1.4` and the two `REQ-CR-1.22` tests still write outside a transaction.** Unchanged
from the previous session and unchanged by this one. Their safety is entirely the `finally`.

**A green mutation is a claim about your mutation before it is a claim about the test.** This
session produced a second, sharper case than the one already written up: an assertion guarded
by *two* independent conditions cannot prove either. Ordinal 1 was shielding the Posted entry,
so perturbing the expected value went red for the wrong reason and looked like proof. Ask what
else could be doing the work. See
`CompoundedLearnings/articles/testing/mutation-proves-liveness-not-aim.md` — this belongs in
it as an amendment and has not been written.
