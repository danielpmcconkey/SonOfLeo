## Design decisions (settled — do NOT re-litigate)

1. **Orchestrators keep their sealed internal transactions.** No `DbTransaction option`
   escape hatch, no savepoints. Dan explicitly refused a test-convenience backdoor in
   mainline code. Creation and voiding are the two legitimately-atomic multi-write flows.
2. **`JournalEntryFetching.fs` needs NO transaction parameter.** It writes nothing and
   no write orchestrator calls it. The earlier idea died with the rollback plan.
3. **Zero Src changes.** The entire punch list is test-side. (fsharp-guard enforces this.)
4. **Tests that commit via an orchestrator must clean up after themselves** in `finally`
   using `_Cleanup.fs` helpers — CLI-test pattern (`mutable idToCleanUp`). The dispose-time
   TRUNCATE is a backstop, not a license. Dan: "I don't want one test polluting the others."
5. **Voiding happy-path tests use consumable fixture victims** (Dan approved). Reserved
   un-voided fixture JEs, one per test; their voided end-state is by design.
