#### Test data approach pivot

Original approach: hand-craft fixture entries at various lifecycle states. Failed because
`createStageEntryForTest` inserts headers with hardcoded `Ingested` status and transitions
are just audit records — the header status column never gets updated.

New approach (Dan's idea): Hobson built a 10-entry test data set
(`HobsonsNotes/bd-stg-test-data-guide.md`) modeled on real checking account imports. Tests
build `BaseStageRawRow` lists in F# with relative dates and run the full
`ingestRawToStageThenDeduplicateAndClassify` pipeline inside rolled-back transactions.
Entries land in their natural lifecycle states.

The test data is constructed in `StageTestData` module (in `StageEntryIngestion.fs`).
`StageTestData.runPipeline context` runs the full pipeline and returns
`IngestionFullResult`. All integrated tests use this.
